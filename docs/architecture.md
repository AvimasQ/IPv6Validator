# Устройство проекта

## Модули

| Файл | Назначение |
| --- | --- |
| `src/ipvalidator.py` | регулярные выражения, проверка и поиск адресов |
| `src/main.py` | командная строка и интерактивный интерфейс |
| `tests/conftest.py` | наборы валидных и невалидных адресов |
| `tests/test_validator.py` | unit-тесты валидатора |

## Проверка IPv6

Проверка выполняется в два этапа.

1. Регулярное выражение `_IPBASE` проверяет синтаксис:
   * адрес состоит из восьми гексетов либо использует `::`;
   * гексеты записаны строчными шестнадцатеричными цифрами;
   * ведущие нули отсутствуют;
   * `::` заменяет не менее двух нулевых гексетов.

   Для гексетов используются шаблоны:

   ```regex
   _H_NZ = (?:[1-9a-f]|[1-9a-f][0-9a-f]|[1-9a-f][0-9a-f]{2}|[1-9a-f][0-9a-f]{3})
   _H_Z  = 0
   _H    = (?:_H_NZ|_H_Z)
   ```

2. Функция `_consecutive_zeros` проверяет каноничность сжатия:
   * без `::` не должно быть прогонов из двух и более нулей;
   * с `::` максимальный прогон нулей слева от `::` должен быть строго
     меньше количества сокращённых гексетов;
   * максимальный прогон справа должен быть не больше этого количества.

Строгое неравенство слева гарантирует, что сокращён первый из самых
длинных прогонов. Нестрогое неравенство справа допускает равные по
длине прогоны после `::`.

## Идентификаторы зон

IPv6 с зоной проверяется шаблоном `({_IPBASE}){zone_pattern}`. Формат
зоны по умолчанию:

```regex
(?:%[A-Za-z0-9_.-]+)?
```

Пользовательский шаблон компилируется с кэшированием через
`lru_cache`. Если шаблон некорректен, выбрасывается `ValueError`.

## Поиск

Шаблон поиска дополняется границами токена:

```regex
(?<![0-9A-Za-z:%_-])(_IPBASE)(?![0-9A-Za-z:%_-]|\.[0-9])
```

Это не позволяет вырезать адрес из более длинной строки:

* `2001:db8::1::2`;
* `x2001:db8::1`;
* `2001:db8::1.5`;
* `::ffff:192.168.0.1`.

Зона в режиме поиска записывается лениво, чтобы не захватить точку в
конце предложения:

```regex
(?:%[A-Za-z0-9_.-]+?)?
```

При этом зоны вида `eth0.100` и `my-zone` распознаются полностью.

## Поток данных

* `find_ipv6()` и `find_ipv6_zoned()` работают с готовой строкой.
* `find_ipv6_in_file()` читает файл и передаёт текст общему поиску.
* `find_ipv6_in_url()` скачивает страницу через `requests`, проверяет
  HTTP-статус и передаёт текст общему поиску.
* `main.py` выбирает режим работы, обрабатывает ошибки и печатает
  результат.

## Ограничения

* Поддерживается только каноническая шестнадцатеричная запись IPv6.
* Смешанная запись с IPv4 (`::ffff:192.0.2.1`) считается некорректной.
* Для поиска по URL поддерживаются только `http://` и `https://`.
* Формат идентификатора зоны не стандартизирован RFC 4007, поэтому при
  необходимости его нужно задавать явно.
